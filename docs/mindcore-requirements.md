# MindCore — 需求与已定事项

> 更新：2026-08-17 · 状态：方案讨论阶段，尚未开始编码
> 本文只收录已经确定的需求与决策。文末「待定事项」中的内容全部没有结论，不作为设计依据。

## 1. 项目定位

一个 AI 数字角色系统：同一个角色通过统一的输入输出接口，接入聊天软件、网页 App、Live2D、3D、语音、游戏等多种表现端；有动作、会用工具、能打游戏。

## 2. 核心需求

### 2.1 内核与表现分离

- 系统分为两部分：**内核** 与 **外部程序**。
- 内核只负责定义统一的输入输出接口，以及模型接入。
- 模型自行对接 API；种类可变（纯文本 / 识图 / 语音），随时间发展可替换，内核可更新。
- 外部程序作为包装器，适配各类表现端（聊天软件、Live2D、3D 动作、游戏等），并组装成最终产品（如网页 App）。
- 所有表现端都经由同一套统一输入输出接口实现。

### 2.2 流式与打断

- 核心必须是流式输入输出。
- 输出过程中可以被打断。
- 过程中能够使用工具。
- 依靠多个模型协同实现上述效果（协同的具体方案未定）。

### 2.3 一切即插件

- 除内核外一切皆插件；一切都能靠插件改变，插件要能改变一切，保证长期发展空间。
- 插件与插件之间能够通讯。
- 插件能够调用 LLM——例如生成更深层次的回复时，调用记忆、人格等。
- 记忆、人格等能力以插件形式组织。
- 插件可以承担前端（如配置页面）。

### 2.4 心流系统

- 有一个「主大脑」/ 统一中枢，控制角色的所有动作。
- 内核的反射、情绪表达需要专门组织设计（具体方案未定）。

### 2.5 多实例与多人格

- 支持多个内核实例同时运行；已定形态：**单进程多实例**。
- 多个人格负责多个服务（同样以插件方式组织）。

## 3. 已定技术决策

| 事项 | 结论 |
|---|---|
| 语言 / 运行时 | TypeScript + Node.js，内核 / 外部程序 / UI 同一技术栈 |
| 运行形态 | 单进程多实例 |
| 既有 Go 原型 | 不再推进 |
| 设计原则 | 实现保持简洁，拒绝过度设计 |

## 4. 待定事项（均无结论）

以下话题在讨论中出现过候选方案，但均未拍板：

- 心流 / 统一中枢的具体方案（状态管理、打断决策、任务挂起与恢复等）
- 内核 ↔ 表现端的协议与事件格式
- 内核内部模块划分与库选型（事件总线、取消机制、模型网关、存储、通讯等）
- 插件机制的具体设计（加载方式、声明格式、扩展点、热重载、权限，以及插件在内核侧 / 外部程序侧的分布边界）
- 反射与情绪的具体实现
- 记忆系统的具体设计
- 多模型协同细节（打断实现、说话中调用工具、端点判断等）
- 仓库结构与开发路线 / 里程碑
