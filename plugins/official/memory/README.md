# memory · 长期记忆（按人组织）

## 是什么

她是同一个人：网页里新开一个对话、QQ 私聊、群里，跟她说话的如果是同一个人，她都该认得、记得上次聊到哪。
本插件把聊过的东西压成三层存进本地库，开口前按「这次在哪、对谁说、在聊什么」取几条放进提示词：

```
短期   最近的对话原样（内核 history，action-reply 取；群里由 group-policy 的阅读窗口挑）
中期   每个会话每攒一段（或安静下来）就用 memory.summarize 压成一段摘要 + 几条「什么时候会想起它」的线索
长期   人物印象：每个跟她打过交道的人一条——这人是谁、聊过什么、对她什么态度、几条确认过的事（每条记来源）
       群印象：这个群平时聊什么、有什么梗、氛围怎样
```

落点照 handbook §9.4：听 `log.appended` 写入、`beat/gather` 给导演材料、`reply/prompt`（action-reply 的水线）给发言者补一段；
存储用 storage-sqlite 的 `db` 裸句柄开自己的表（`mem_*`），日志被清空（`/api/clear`）也不动它们。

## 设计

### 记忆按「人」，不按频道

- **人的 id**：`<平台>:<sender.id>`（`qq:12345`、`web:web-user`）。同一个人在不同平台用 `aliases` 并成一个
  （`/config set plugins.memory.aliases {"qq:12345":"web:web-user"}`）——主人的 QQ 号并到网页用户上，她就知道是同一个人。
- 网页用户默认就是「主人」（`ownerName`）。
- 群里的机器人（group-policy 的服务 `bots` 认出来的）不建人物印象、不算跟她打过交道的人；没装 group-policy 就当没有机器人。
- 中期摘要按会话写，但记下这段里有哪些人；召回时按人找：新开一个网页对话，开头几句她就能想起「上次（在另一个对话里）聊到……」。
  还没来得及压成摘要的上一个对话，直接带最后几句原话。

### 群里的私事不往别处说（召回按来源过滤）

每条摘要、每条人物事实都带来源会话。召回时：

| 现在在 | 能想起 |
|---|---|
| 网页 / 私聊（一对一），对方本人 | 对方的一切：印象、所有来源的事实、对方参与过的摘要（别处来的标明「群 X」「私聊」） |
| 网页 / 私聊，话里提到的别人 | 那人的印象 + 那人**在群里公开说过**的事；那人私聊里说的永远不给别人 |
| 群 X | 说话的人与提到的人的印象；**只有来源是群 X 的**事实与摘要；群 X 的印象 |

**印象也分公开 / 私下**（`mem_people.impression` / `private_impression`）：一对一里聊出来的只写进私下印象，群里形成的写进公开印象。
私下印象只在跟本人一对一时想得起；别处（群里、跟别人聊）只给公开印象——否则「他最近失恋了」会经印象漏到群里（实测踩过）。

「话里提到的别人」：最近几句里出现了某个打过交道的人的名字（两个字以上），就把这人也想起来（「老王是干啥的」）。

导演提示词另有一句：标了来源的事别拿到别的群说；私聊里聊过的事在群里也别主动抖出来。

### 超大群：印象只给打过交道的人建

几万人的群不能每人一条印象。只有「跟她打过交道」的人才建印象、进摘要的人物更新：
@ 过她 / 叫过她名字 / 回复过她，或者她开口前最后说话的那个人。其他人只记名字和最后出现的时间。
群的中期摘要攒够 `groupChunk` 条才压一次（私聊 `chunk` 条），安静 `idleSec` 秒也压——更早的事靠它，不靠原文。

### 写入：一次调用三件事

攒够一段 → 一次 `memory.summarize` 调用，提示词三部分：
中期摘要（只根据这段总结、不编造、出 summary + recall_cues）+
去污染规则（玩笑、猜测、机器人自己的话、被纠正的旧值都不写成事实；发言者与事实严格绑定）+
人物印象（印象是一段自然语言，不是关键词）。输出 JSON：

```json
{"summary":"…","recall_cues":["…"],"people":[{"id":"qq:20001","impression":"…","facts":["…"]}],"group":"…"}
```

`people` 只含这段里跟她打过交道的人，给的是**更新后**的整条印象（旧印象一并给模型）；事实追加、按文字去重、每人最多 `maxFacts` 条。
解析用 JSON.parse（不用正则）；失败重试一次，再失败这段丢掉并记 `memory.failed`。

### 召回：先做简单的

不上向量库：当前会话的最近摘要 + 这些人的印象与事实 + 用双字词重合度给其余可见摘要（含 recall_cues）打分取前几条，
总长不超过 `recallChars`。给发言者的段落放在 `PROMPT_ORDER.memory` 槽位，每条带来源。
「这些人」= 对话窗口里说过话的人都算（最后说话的在前，最多 `recallPeople` 个）+ 话里提到的；原来只看最后 8 句里的 3 个人，
群里热闹时阅读窗口前半截那几个人她就「不认识」了（群里的人物也要带上下文）。
给大脑的材料：唤醒原因里的人 + 窗口里说过话的人，各一句印象，再带两条这里能说的事（群里只带本群来源的；
这拍只要有群，一对一的人也不带事实——大脑的一块材料是全局的，私事不能顺着它进群）。

## 暴露什么

- 表：`mem_people`、`mem_episodes`（中期摘要）、`mem_groups`、`mem_cursor`（各会话压到哪了）。
- 日志：`memory.summarized { channel, turns, people, chars }`、`memory.failed`。
- `reply/prompt` 一次性段落「你记得的」；`beat/gather` 材料块「你对他们的印象」。
- 模型角色 `memory.summarize`（provider 里没绑就走 `default`）。
- 网页：状态卡「记忆」（各层条数、攒着没压的）；面板「记忆 · 人」（印象、事实、清掉印象 / 删人）「记忆 · 群」「记忆 · 中期摘要」。
- 命令 `/memory`（各层条数）· `/memory flush [频道]`（现在就把攒着的压掉）· `/memory who <名字或id>` · `/memory forget <id>`。

## 怎么改

`/config set plugins.memory.<键> <值>`：`chunk` / `groupChunk` / `idleSec`（多久压一次）、`maxFacts`、`recallChars`、`ownerName`、
`aliases`（把几个账号并成同一个人，如 `{"qq:10001": "web:web-user"}`：主人在 QQ 上也想得起网页里的事）。
想让摘要用别的模型：`/config set plugins.provider-openai.roles {"memory.summarize":{…}}`（只是一份补丁，不会冲掉别的角色）。
