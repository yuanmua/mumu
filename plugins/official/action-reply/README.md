# @mumu/action-reply

**是什么**：`reply` 动作，角色唯一的说话方式。流式调用 `performer` 角色，边生成边经内核 utterance 送到表现端，被打断就停在那一个字。

**参数**：`guidance`（大脑此刻心里想的，第一人称，可省）· `append`（补充刚才的发言）· `tier: 'deep'`（认真答：改用 `performer.deep` 角色，provider 里可绑更强的模型；已经先应过一句时，大脑一般配合 `append` 用）· `reflex`（快回：大脑写 `quick:true` 放行、或脊椎兜底时带上，改用 `performer.reflex` 角色，provider 里可单独绑一个首字快的模型，如本地端点；大脑放行的另带 `quick:true`，只作标记）· `brief`（简短模式，见下；快回自动是简短模式）。
大脑 = mind-default 插件，脊椎 = reflex 插件（旧称导演、反射）。

**简短模式**（`reflex` 或 `brief`，2026-10-22 真群反馈后加）：对方只是「在吗」「嗯？」时，真人回「在」「咋了」。
不管的话她会回一串，还给自己编来历（实测「在吗」→「在呢在呢刚被叫去做题了，脑子还热着」，群友一问「什么情况」大脑又把这件编的事解释一遍）。
- 提示词加一段 `reflexHint`（默认：只回一条、六个字以内、别编你刚才在干嘛、别分段）；
- 输出机械收住（`clipReflex`，逐字看，不用正则）：说出字后的第一个句末标点（带上）、说够三个字后的逗号或空格（不带）、`<|br|>`、或满 `reflexMaxChars`（默认 8）字就不再出字。
  之后的表情 / 表情包标记照发（「好嘞！<|sticker:得意|>」的图不丢）。
- `performer.reflex` 的 `maxTokens` 在 provider 配置里压到 60（库里覆盖，不改清单）。
- 大脑回简单招呼一般用 `quick`；想带点自己的念头再应，就 start reply 自己带 `"brief":true`。

**模型角色**：`performer`（大脑带想法起的回复）· `performer.reflex`（快回：quick / 脊椎兜底）· `performer.deep`（认真答）。三者在 provider 配置里各自绑定。

**没在做事就别承诺、别编进度**（`idleHint`，2026-10-22 真群后加）：这个对话里没有在跑的动作（reply 以外）时，每次发言（快回也算）加一段【手头】：
没开始的事别说「这就去」「在弄了」，被问进度就老实说没在做 / 没接这活。真群：「截图看看桌面」反射答「好，我这就去弄」却什么都没起；
被问「实时汇报项目进度」时什么都没在跑，她编了「刚建了个文件夹」。大脑「应一声 + 起动作」时 reply 排在动作后派发，那时动作已在跑，这段不出现。

**汇报动作结果**（`report.ts`，2026-10-22 真群后加）：DSH 跑完水杯题，大脑两拍的 guidance 都写着「n=8 k=3 最坏要问 5 次」，
发言者却两次去接群里最后那条挑衅的话，结果一个字没提——【此刻你心里想的】夹在中间，压不过结尾【要求】的「把握当前的话题」和历史最后一条闲话。
现在：本对话里有还没汇报的动作结果（`resultKinds`：`computer.result` / `dsh.result` / `extend.result` / `search.result`，`resultWindowSec` 内，之后还没有带想法的 reply 开过口；快回不算），
这次发言（非简短模式）加一段【这次开口是汇报】：围绕结果说、别接群里最新的闲话，附结果原文摘录（压成一行，`resultMaxChars` 字）。排在【现在】之后、【要求】之前（`PROMPT_ORDER.time + 10`）。

**念头放在最后一轮**（2026-10-22 全量测试后）：同一种病的通用版——bot-ignore 里大脑 guidance 写「接小林那句吃辣」，发言者却说出「小D酱能不能歇会，烦不烦啊」；
real-ccb 里 guidance「不理那两个，转去接小圆圆的暴风雪」，她说出「两个人都刷一样的，不腻吗」（历史最后一条都是机器人 / 刷屏的 @）。
先试过在【要求】前再加一段【这次开口】提醒，没用。现在带 guidance 的非简短发言，在消息列表末尾加一轮 `[旁白] 你此刻心里想的：…——接谁、接哪句以这个为准`
（与 append / 对方没说话的旁白合成一条）：模型记得最牢的是最后一轮，念头放那里才压得过历史末尾那条。【此刻你心里想的】系统段照旧保留。

**提示词怎么拼**

```
system:  按 PROMPT_ORDER 统一排序 ——
         人设(persona) · 腔调 · 心情(emotion) · 表情教学(expression) · 【刚才发生的事】工作记忆 · 【此刻你心里想的】guidance · 时间(clock) · 【要求】(persona)
history: 对话原样 user/assistant 轮次（按频道，默认 30 轮；群里由 group-policy 换成阅读窗口）
         最近几张图的原图挂在发的那条 user 轮次上（见下）
user:    只在历史以自己结尾时加一条 [旁白]，给模型开口的契机
```

**原图跟着那条消息**（2026-10-23）：重要的图片（聊天里那几张）直接给到上下文，避免转述成文字后聊天结果跑偏。
组好最终历史后问服务 `images`（surface-onebot 提供，现取不注入；没装就全用文字）这段里哪几轮带原图：那几轮的文字用换过占位的（描述换成「[图片]」），
原图作为消息的插件层字段 `images` 交给 provider-openai（类型 `ImageMessage`）。选图规则（每会话最近 3 张、15 分钟内、总共 ≤2MB、表情包也带）在 surface-onebot 的 `images.inline` 配置里。
快回（`performer.reflex`）不带，只求快；`performer` / `performer.deep` 带。

工作记忆与 guidance 是本次调用才有的，作为一次性段落交给 `ctx.prompt.assemble('performer', extras)`，走同一套槽位（`memory` / `thought`），所以能排在「要求」之前而不是拼在整段尾部。

v1 把导演指示塞进 user 轮次（「[导演指示] 自然回应」），模型把它当成对方在下命令，语气立刻变客服。现在引导只出现在 system 里。

**marker 通道**（语法 `<|通道:值|>`，由内核流式解析）

| 通道 | 处理 |
|---|---|
| `emo` / `act` / 其他 | 原样作为 `Part{kind:'marker'}` 发给表现端 |
| `br` | `Part{kind:'break'}`：表现端分成下一条消息 |
| `tool` | 变成 `performer.tool` 感知交给大脑并行处理，发言不停 |

**分段写法归一化**（`br.ts`）：模型该写 `<|br|>` 分段，实际常写成别的——
- HTML 的 `<br>`：它若当文字说出去，会进 delivered、进历史和记忆，下一轮又喂回给模型，越学越多，网页上显示成字面「<br>」（实测）；
- 换行：三句挤在一条气泡 / 一条 QQ 消息里（实测「…起哄\n\n周五九点我记着呢…」）。
- 残缺的标记：`<|br>`、`<br|>`、`<|br|`、`|br|` 之类少一边（实测 QQ 里出现字面「叫可乐好可爱<|br>三岁了还黏人」；`<|br>` 还会让 `parseMarkers` 一直吞到下一个 `|>`）。左边 `<|` / `<` / `|`、右边 `|>` / `>` / `|` 的组合都认，只有一边的不认（`<br` 可能是 HTML 写到一半，`|br` 可能是正文），`<|br` 除外。

所以进 `parseMarkers` 之前把完整出现的 `<br>` / `<br/>` / `<br />`（大小写不论）和换行都换成 `<|br|>`，被切在两个 chunk 之间的也认；
连着几个换行算一个，紧挨着已有 `<|br|>` 的换行不再加（免得分出空消息），开头结尾的换行丢掉。换行怎么算由配置 `newline` 决定：
`all`（默认，任何换行都分段——聊天里一条消息本来就是一句话）、`double`（只有空行分段，单个换行变空格）、`none`（不管换行）。

喂回模型的她的历史发言同样写成 `<|br|>`。内核只把 `Part.text` 计入 delivered，分段说出去的话在历史里是粘成一串的（实测「…好吗你才机器人呢…」），
所以从日志的 `utterance.part` 找回 break 的位置插回去（`selfSegments`），旧的换行与 `<br>` 也一并换掉：她看到的自己的历史就是她要模仿的写法，
示范对的比在提示词里讲「换行就是另发一条」稳。这是已知写法的归一化，不是用正则解析模型的决策。

**工作记忆按会话过滤**：内核的工作记忆是全局的；来源是动作实例的条目（`reply#3` 的「刚说完：…」、`computer#1` 的结果）只放进同一频道的发言里，
别的会话的不放——多会话时她会把那边刚说的话在这边复读一遍（实测）。来源不是动作的（kernel、guard 之类）仍全局。

**结算**：`utt.end()` 后按 delivered 写一条工作记忆（被打断时写清「对方实际听到的」与「没说出去的」），下一次开口不会重复。

**怎么改它**

- 历史轮数：`historyLimit`；候选池：`historyPool`（出厂值见 `package.json`；候选池要比群里的阅读窗口想翻的范围大）。

**可改点 `reply/prompt`**（waterfall，载荷类型 `ReplyPrompt` 随本插件 `index.ts` 导出）：组装前先取最近 `historyPool` 条作候选池，
连同 `{ actionId, channel, reflex, append, limit, extras }` 过这条水线，最后只留 `history.slice(-limit)`。
段落的 `render()` 不知道这次在哪个频道、对谁说，所以跟频道有关的材料从这里进：group-policy 在群里换成「阅读窗口」，memory 往 `extras` 补召回的记忆。
没人拦 = 最近 `historyLimit` 条，和以前一样。
- 想让某类 marker 变成别的 Part：在这里加一个分支，表现端不认识的 kind 会被忽略（能力降级）。
- 想换发言模型：provider 配置里 `roles.performer`。
