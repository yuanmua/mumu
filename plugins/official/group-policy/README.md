# group-policy · 群聊读空气 + 多会话调度

## 是什么

她同时挂在好几个 QQ 群、几个私聊和网页对话里。真人用手机是这样的：大多数群消息只是扫一眼；
有人 @ 她、私聊找她才点进去回；一次只在一个会话里打字；忙着做别的事时群里只回找她的。
本插件就管这件事，三块：

1. **接话意愿**（`percept/pre-beat`）：给「群里不是冲她说的话」打一个接话概率，掷骰子决定要不要唤醒大脑。
   唤醒之后接不接、接什么仍由大脑定（mind-default 的【群聊】规则）；被压掉的话照样进日志和历史。
2. **手机通知栏**（`beat/gather` 材料块「手机上现在的情况」）：所有活跃会话各自的未读数、最后一两句、有没有人 @ 她、
   她此刻「在」哪个会话、是不是正忙着用电脑——大脑据此决定先回谁、要不要切过去。
3. **阅读窗口**（action-reply 的 `reply/prompt` 水线 + `beat/gather`）：几万人的群不能把历史全喂给发言者，也不能只喂眼前几句。
   群频道里她「读」最近几十条（消息越密读得越少）+ 更早提到她的 + 她最近几次开口的上下文 + 正在和她聊的那段；大脑与发言者看同一个窗口；
   窗口里出现的人各是谁、最近在群里干嘛、窗口里没带上的他还说过什么，另给一块「在场的人」（people.ts）；更早的靠记忆插件的中期摘要。

总原则：**和真人一样，想聊就聊，不想理就不理。** 不用硬性限额「管」她，意愿由她此刻的状态决定——
心情好、喜欢这个群、聊到她感兴趣的就多说，甚至连着说；心情差、烦这个群、话题无聊就整段不理。

@ 她、叫她名字、回复她的消息：surface-onebot 改成 `message` + `urgent`，**大幅加权但不是 100% 必答**（`cold.ts`）：
接的概率 = `at.base` 0.95 × (好感 × 心情)^`at.sensitivity`。平时约 0.95；烦的群 + 心情差会低很多。
没掷中就把这一拍的 kind 换成 `message.cold`——脊椎不抢答，大脑照常被唤醒，材料里有一块「冷 @」告诉它「你此刻懒得理、脊椎没替你回」，
它自己决定敷衍一句还是不回。**主人**（guard 的 `owners` ∪ 本插件 `owners`）@ 她必答。
同一个人 `at.perPersonSec`（120）秒内连着 @ 她、刚在这个群敷衍过一句、@ 她的话里带低俗 / 骂战 / 政治的词、斗嘴够了：
都只是「不抢着回」（冷 @），大脑一定会被叫醒，材料里写着这句的情况（见下文「读空气不写死」）。机器人的 @ 另算，见「群里的其他机器人」。
她在「懒得理」的群里开口时，发言者会收到一句态度提示（敷衍、短）；「想聊」时也说一声。

### 读空气不写死「不接」+ 按人累积的脾气（temper.ts，2026-10-22）

真群日志里原来是「读空气：没接 · 低俗 / 骂战 / 政治话题（几把），不接 · p=0.00」「DeepSeek酱 是机器人（名单），不理 · p=0.00」这样硬判的。
真人不是这样：**这种话也不是完全不接，强 @ 加点名多了会烦，会生气、会视而不见甚至拉黑这个人；该由她自己判断，不写死在代码里，她的底色是纯洁善良的。**
**机器人的话可以回，但要完全明白那是机器人的无用废话。** 这类判断都照此处理。所以：

- **内容类的「不接」一条都不写死**。词表（`tabooWords`）、机器人名单这些判断材料都还在，但只用来**给大脑写一行提示**，不直接决定 p：
  - 带低俗 / 骂人 / 政治词的话：吸引力乘 `tabooFactor`（0.5，不归零），`why` 写「带低俗 / 骂人 / 政治的词（几把），接不接她自己定」；被 @ 时不抢着回、交给大脑；
    正在和她聊的人带了脏字只是「在聊」的分再乘这个系数。原来一律 p=0。
  - 机器人说的话：乘 `bots.attraction`（0.15），`why` 标「说话的是群里的机器人（程序的套话）」；机器人 @ 她按冷 @ 以 `bots.atWake`（0.5）的概率叫醒大脑。原来 wake=false、p=0。
  - 同一个人刚 @ 过又 @、刚在这个群敷衍过：原来 wake=false「连想都不想」，现在都叫醒大脑（冷 @）；同一个人接着说、前一句刚叫醒过她：乘 `sameSenderFactor`（0.3），原来硬 0。
  - 保留的硬 0 都不是对「这句话」的判断，而是她的处境：她正在这个群说话、群倍率被人设成 0、忙着做 `busyActions`、`maxPerMinute`（默认关）。
- **大脑材料【读空气】**（`beat/gather`）：最近两分钟里冲她来的 / 叫醒了她的几句各是什么情况——带什么词、是不是机器人、这人今天第几次 @ 她、她对他多烦；
  正在不理谁、还剩多久。开头一段写明她的人设倾向（纯洁善良，这种话一般不接也不接梗，**但那是她自己的选择不是禁令**；被纠缠先岔开、委屈，烦了带出不耐烦，再往上可以不理，拉黑是最后手段；被骂先委屈不对骂）。
  mind-default【群聊】与 persona【要求】的对应条目同样改成倾向描述。
- **按人累积的脾气**（`temper.*`）：「骚扰度」按**群 + 人**记（同一个人在 A 群烦她，不影响他在 B 群跟她正常说话；全量测试里曾一次 ignore 泄漏到所有群），从真源投影（启动回放全部存量），冲她来的话才算：被 @ / 点名 `at` 0.5、`repeatWindowSec`（120）内又 @ `repeatAt` 1、
  带低俗 / 骂人词冲她说 `taboo` 2、她已经岔开过这个低俗话题（他的、或这个群里的，10 分钟内）还拿它追着问 `pester` 2（材料里写明「你 N 分钟前已经岔开过这个话题——岔开过的不用再接」；全量测试里她岔开一次后又逐句回了五句）、骂她（`affinity.insultWords`）`insult` 2、让她自证是 AI（`callBotWords`）`callBot` 1.5、三分钟内冲她说够 `burstCount` 句 `burst` 1、机器人 @ 她 `botAt` 0.3；
  按 `halfLifeMin`（60）半衰期消气。乘 `sensitivity`（脾气松紧，设置页滑块）后 ≥3 「有点烦」、≥8 「很烦」、≥14 「忍无可忍」——**这些只是给大脑看的形容词，不触发任何动作**
  （一个人连着拿低俗话 @ 她：第 1 句一般、第 2 句有点烦、第 3 句很烦、第 5 句带骂人忍无可忍；mind-default 教她按层次来：有点烦时只岔开，很烦才不耐烦，忍无可忍再考虑不理）。
  她开口要回的人里有让她烦的，发言者收到一段【对这个人的态度】（可以不耐烦、冷淡、短，但别对骂、别说脏话；正在不理的人当没看见）。主人不算。
  「/ccb @她」这类发给群里机器人的指令：`cold.ts` 不抢着回，材料写明「@ 你只是指令的参数」（真群她曾每次都接「又ccb我」）。
- **「不理他了」是大脑的决定**：动作 `group.ignore`（`{"who","mode":"ignore|block|forgive","minutes","why"}`），写日志 `temper.ignored` / `temper.forgiven`，本插件从日志投影、在 `percept/pre-beat` 最外层执行：
  被不理的人的话不叫醒她，@ 她也把 kind 换成 `message.ignored`（脊椎、冷 @、排队都只认 `message`），surface-onebot 不按 urgent 打断她；`group.policy` 的 `why` 写「你决定不理他了（原因），还有 N 分钟」；
  到期自动恢复（不写日志，按日志里的 until 算）。**ignore 只管那个群**（日志带 `channel`；大脑在群外决定、没带群的才各群都算），**block 跨群**（拉黑是对人）；
  forgive 带群只解那个群的不理，不带群连拉黑一起解。ignore 默认 `ignoreMinutes`（30）、最长 `ignoreMaxMinutes`（240）；block 默认 `blockHours`（24）、最长 `blockMaxHours`（168），
  memory 插件听同一条日志把「我拉黑过他（原因）」写进她对这个人的公开印象 + 一条带来源的事实（ignore 只记事实）——下次见到还记得。主人（guard.owners ∪ 本插件 owners）不能被不理 / 拉黑，动作直接拒绝。
- **看得见**：面板「脾气（按人）」（谁、她对他、骚扰度、因为、她的决定；「原谅」按钮写 `temper.forgiven`）；`GET /api/group-policy/temper`、`POST /api/group-policy/temper/forgive`。
- 模拟器场景 `temper-harass` / `temper-dirty` / `temper-bot`，以及按真群乙（2026-10-22）日志原样做的 `real-ccb`（/ccb 指令她每次都接）、
  `real-ml`（ml / 淫乱问题她逐句接）、`real-bot-chat`（DeepSeek酱 的套话她当真斗嘴）——都是点名才跑，`scripts/fake-onebot/temper-scenes.ts` 文件头写着她当时错在哪、现在要求什么。

## 设计

### 接话概率

```
p = 打分(这句话) × talkValue(全局话多话少) × 群倍率(rates，手动) × 好感(自动) × 心情(emotion) × 时段系数(timeRules)
    × 专注系数（她正在别的会话里说话 → focus）× 私聊优先（有私聊在等她回 → privateFirst）
```

**打分先分两种状态**（像人一样：没在聊天状态时少回一点，看一眼就过去；在聊天状态就接着多聊几句，
而不是机械地都用一个概率；`group.policy` 日志与网页「接话判断」每行标着「在聊 / 没在聊」）：

- **在聊**——她参与的话题还开着、这句在接它（`topics.ts`）；或她刚说完、这句在接她的话；或这句和她参与的话题线对得上。
  意愿是「接着多聊几句」的量级：三项取最高，再按她在这个话题里已主动接过的轮数衰减（× `topic.inTopicDecay`^轮数）——
  接得越多越收着，兴趣话题起点高，`topic.maxTurns` 只是安全网。正在和她聊的人接着说（convo.ts）也在这里：起点 `followUp`，按她在这段对话里接过几句衰减（原来不打分、直接叫醒）。
- **没在聊**——像人刷群：`base` 是「偶尔看一眼」的量级，不是 0 也不是每句都看；有人在问往上，是她喜欢的话题再乘上去（两种状态都乘）。看了要不要插话不在策略层替大脑定，
  它自己有【群聊】规则（mind-default）。**叫醒 ≠ 开口**：大脑材料多一块「这次为什么叫醒你」（`wakes.ts`，最近一分钟叫醒过它的判断各是在聊还是没在聊），
  没在聊时写明「你没在这个群聊着，刷到这一眼；有想说的就说，没有就过」——模拟器 flood / boring-rocket 里没有这块时大脑被叫醒就插话，应了一声「在」之后就卷进去了。
  原来还写「默认不插话、看一眼就过」，2026-10-23 去掉：读空气那一掷本身就是「偶尔看一眼」，大脑再默认不说是双重把关
  （真群回放里没被 @ 的叫醒大脑只说了 11%，她自己开口只占别人消息的 0.7%）。

取最高的往上项，再被最低的往下项压住：

| 类 | 条件 | 键（默认） |
|---|---|---|
| 没在聊 | 普通一句：偶尔看一眼 | `base` 0.08 |
| | 有人在问（`？`/`?` 或含 `questionWords`；长短不限，是不是认真问交给大脑） | `question` 0.3 |
| | 冷场 `coldSec` 后的第一句（默认关） | `cold` 0 |
| 在聊（取最高 × 衰减） | 正在和她聊的人接着说（见「正在对话」）：不用看共有词，按她在这段对话里接过几句衰减 | `followUp` 0.4 |
| | 她参与的话题还开着、这句在接它（见「话题生命周期」） | `topic.inTopic` 0.3 / 兴趣话题 `topic.interestInTopic` 0.6 |
| | 她刚说完 `followWindowSec` 内、中间不超过 `followMaxBetween` 句，而且这句像是冲她那句来的（有共有的双字词，或是在问）；光时间挨着不算 | `followUp` 0.4 |
| | 还在聊她参与的话题：`relatedWindowSec` 内，与「她上一句 + 她接的前两句」共有 ≥ `relatedMinOverlap` 个双字词，不限中间隔几句；对不上了（换话题）就回到「没在聊」 | `related` 0.4 |
| 往下（两种状态都压） | 同一人连发 ≥ `spamCount` 句（中间没人插话） | `spam` 0.03 |
| | 整个群一分钟超过 `floodPerMinute`（默认 20）句（刷屏；12 句/分钟在活跃群里是常态，不算） | `flood` 0.03 |
| | 纯表情（`[表情]`、`[表情包…]`） | `emojiOnly` 0.03 |
| | 灌水：去掉标点只剩一两个字（「6」「草」「在吗」「哪家」，是不是问句都算） | `shortChat` 0.01 |
| | 复读：和前面几句别人的话一字不差 | `repeat` 0.01 |
| | 给机器人发的指令（去掉开头的 @ 后以 `/` 开头：`/ccb @某人`、`@幻梦 /打卡`） | `command` 0.01 |
| | @ 别人、引用别人的话（是在跟别人说） | `atOther` 0.03 |
| | 最近只有两个别人在一来一往 | `chatter` 0.05 |
| 乘数（不归零） | 这句或前面 `tabooWindowSec`（120）秒内别人刚说的几句带 `tabooWords`（涉黄 / 低俗 / 骂战 / 政治）× `tabooFactor` 0.5；说话的是群里的机器人 × `bots.attraction` 0.15；同一个人 `sameSenderWindowSec` 内的话已经叫醒过、她还没开口 × `sameSenderFactor` 0.3。都只是材料，`why` 里写着，接不接她自己定（见「读空气不写死」） | — |
| | 是她喜欢的话题：× (1 + k × 感兴趣程度)，乘完封在 `capNonDirect`（0.9）以内——没 @ / 没叫她名字的话再像在接她、再是她喜欢的话题也不到 1，p=1 只留给被叫到（2026-10-23：「在聊 0.5 × 兴趣 ×2」就到 1，real-convo-spam 一句「狗修金」认成猫就每句必接）；感兴趣程度 = 这句和她某条兴趣的**语义相近度** × 那条兴趣的分（interests 插件，0～1）。两种状态都乘：灌水压低的照样低，在聊、有人在问的往上翻。`why` 写「聊到她感兴趣的（航天，相近 0.72）×2.4」 | `interest.k` 3 |
| 硬闸（0，处境不是内容） | 她正在这个群里说话；这个群倍率 0（只在被 @ 时答）；`maxPerMinute` > 0 时这个群一分钟内她已开口那么多次（默认 0 = 不限，节奏交给 surface-onebot 的出口节流）；她正忙着做 `busyActions` 里的动作（`busy` 0 = 群里只回必答）；大脑决定不理 / 拉黑的人（`group.ignore`） | — |

默认值的来历（2026-10-22，四轮）：旧默认（`base` 0.25、问句 0.6、接话 0.6 / 0.7）下 51 条群消息她开口 13 次，过半在跟另一个机器人斗嘴；
第二轮 `base` 0.05、上调项约为原来的四分之一，仍然太频繁（36 条里说了 8 条，还在逐句接低俗梗）；第三轮（不要节拍器、不要冷场兜底）
`base` 压到 0.01、冷场加分关掉、问句要 ≥6 字才加分、兴趣成为主项——重放约每 42 句人话唤醒一次，但模拟器 flood 场景 24 句闲聊大脑一次没醒，
真群里她几乎只在被 @、被点名时醒。**第四轮改成按状态分**（不能压那么低，也不该所有情况都用一个概率）：没在聊回到「偶尔看一眼」（`base` 0.08，
问句 0.3，兴趣 0.6），在聊回到「多聊几句」（0.4～0.7，按轮数衰减），灌水 / 复读 / 纯表情 / 指令 / @ 别人 / 两人对聊照旧压到接近 0；
**第五轮（同日傍晚）在聊往回收一点**：真群她回过某人后对方每句都 p=1 直通（见「正在对话」），又太多了；目标是不必大都接，但比一句也不接稍高一点，有话题还是可以聊——
正在和她聊的人并进「在聊」打分，起点就是 `followUp`，并把在聊的起点整体收到 `followUp` / `related` 0.4、`topic.inTopic` 0.3、`topic.interestInTopic` 0.6（衰减 0.75 不变），
对方连说六句她接一到三句的量级；没在聊的 `base` 0.08 / 问句 0.3 / 兴趣 0.6 不动；
问句去掉 6 字门槛，认不认真交给大脑。`feel.coldBelow / warmAbove` 跟着 `base` 回到 0.04 / 0.12。
**第六轮（2026-10-23 夜，真群记录回放）**：兴趣改成语义乘法后，在 k 1.5 下 600 多句里沾到兴趣的平均只乘 ×1.12，
没在聊时的兴趣话题从原来直接抬到 0.3 掉到 0.1 上下，兴趣叫醒一段只有 5 次；`interest.k` 1.5 → **3**（兴趣叫醒约 20 次，强兴趣一句 ×2.9）。`base` 试过 0.10 / 0.12，和 0.08 的差别在单次回放的噪声以内，
又会把「在聊远高于没在聊」的比例压到 3 倍以下，不动。同时去掉了大脑材料里「默认不插话」（读空气那一掷本身就是「偶尔看一眼」）。
主群 16–18 点 655 条：开口约 3.5%、自己开口约 1.2～1.7%、没被 @ 的叫醒大脑开口 20%～40%，机器人叫醒与冲机器人开口没涨；开口多少主要看大脑叫醒后说不说。
**话题吸引力是主项**（不是每隔多少句就一定要回；话题不像聊就不聊，可以一直无视，直到出现一个真实的话题）：
上表的往上项 / 往下项算出来的数就是这句话的「话题吸引力」（`group.policy` 的 `factors.attraction`，网页「接话判断」每行都写着），
再乘她此刻的状态（话多话少 × 群倍率 × 好感 × 心情 × 时段）。吸引力高：在聊、有人在问，是她喜欢的话题再乘上去（interests 插件给 0～1 的感兴趣程度，
语义相近度 × 她自己维护的兴趣分，`× (1 + interest.k × 分)`；没装 interests 就不乘，不再退回关键词）；
接近 0：灌水（`shortChat`，一两个字）、复读（`repeat`）、纯表情、指令、@ 别人、别人两个对聊；带低俗词、机器人说的只打折不归零。
**冷场后第一句默认不加分**（`cold` 0）：冷场本身不是开口的理由。几十条、几个小时一句不说是正常的——大脑偶尔被叫醒看一眼，多半也只是看看。

**没有开口次数的硬上限**（该限制的是「必须主动开口」的设计，不是开口次数）：一度加过「每群每小时最多主动开口 6 次」，真群里主人说「用电脑算算」
被它压掉了，已删。说不说只看这句话值不值得接；节奏交给 surface-onebot 的出口节流。

**没 @ 她的群消息一律打分，没有直通**（主人不特殊：主人的话也不一定要回，和其他人一样，比如主人在和别人聊天就不用理）。直通 p=1 先后删了三条：
- 「主人在群里说的话一律叫醒」——主人跟别人聊天、发张表情包，她也冒一句碎话（真群：「感觉还得调试一下」→「嗯，边界啊搜索空间」）；
- 「正在和她聊的人接着说」（`convo: true`）——并进「在聊」打分（见下文「正在对话」）：**在聊 ≠ 每句都接**；
- 「像是要她做事」（任务词子串匹配 `task.words`，2026-10-23 删）——「运行」「搜」「帮我」在闲聊里到处都是：真群乙 23:29 Novas「我的日语模块已经分成三份独立运行了」、
  900901 17:55 机器人小鱼「手快是好手快 搜的就是不太对」都被它 p=1 叫醒。子串匹配太粗糙，该看的是这句是不是她喜欢的话题，是就乘上唤醒概率——
  做事的话不再单独认，和别的群消息一样打分：是她喜欢的话题就按语义相近度乘上去（`× (1 + interest.k × 感兴趣程度)`，见下文「兴趣」），不再按词表匹配；真要她做事会 @ 她，走下面的冷 @。代价：主人不 @、随口一句「用电脑算算」不一定叫得醒她。
主人 @ 她仍然必答（冷 @ 那条不掷骰子），这是「被叫到」，不算特殊化。

### 正在对话（convo.ts）

原来聊一个问题不连贯，对方得 @ 她好多遍：只有 @ / 叫名字 / 回复她才算冲她说，对方第二句不带 @ 就回到普通打分，她多半不接。
真人在群里和某人聊上了，对方的下一句默认是在跟自己说。按「群 + 对方 id」记，从真源投影：

- **开 / 续**：她回了某人，或者某人 @ / 叫了她。「回了某人」按事实认，不靠猜：叫醒那一拍大脑的原因里说话的人（mind-default 把 `reasons` 连 sender 落进 `mind.decision`，
  `rooms.ts` 顺着那拍起的 reply → utterance 记到她这句的 `to`）。原来是「上次开口后 @ 她的 / 对话中的 / 最后叫醒过她的那句，都没有就算她开口前别人那句」——
  真群甲（17:53）她回灰灰子时 IIIBeta2III 恰好在她开口前说了句无关的、汇报搜图结果那拍（原因只有 computer.result）一分钟前叫醒过她的路人，都成了「正在和她聊」。
  没有决策信息（脊椎兜底应的一声）时只算冲她说的（@ / 回复她）。
- **对话中**：对方接着说的话（没 @ 别人、不是回复别人、不是收束句、不是纯表情或一两个字、不是无关的短闲话）标 `convo`，**按「在聊」打分，不再直通 p=1**：
  起点就是 `followUp`（0.4；和旁人的区别是不用有共有的词、不用挨着她那句，也算接她的话），她在这段对话里每多接一句乘 `topic.inTopicDecay`（0.75）——0.4 → 0.3 → 0.23 → 0.17，对方连说六句她接一到三句
  （不必大都接，但要比一句也不接稍高一点，有话题还是可以聊；参数宁少勿多），
  同一个人上一句刚叫醒过她、她还没开口再乘 `sameSenderFactor`；话题收尾、刚聊完的冷却不压这条（对话是她和这个人的事）。`why` 写着「正在和她聊的 X 接着说（他这是第 N 句，她在这段里已经接了 M 句、他回了她 R 句）」。
  她说的比他回的多（M > R）每多一句再乘一次衰减：对方不回，她不该一句接一句往上凑。
  真群甲（2026-10-22 17:50–17:58）直通时：她回过灰灰子一句后，他的「哦鲸鲸？」「为什么」「多押韵」每句 p=1，大脑十二秒里三次决定「接住梗」，八分钟开口 14 次。
  在聊就接着多聊几句，没在聊看一眼就过，不该机械地都用一个概率；不叠新机制、能删就删——所以删掉直通、并进两态，没有再加一层。
  无关的短闲话 = 不超过 `convo.chatterMaxChars`（6）个字、不是问句、和这段对话最近几句没有共有的双字词（「摸鱼中」「困死了」）：
  人还在、对话不断，但这句交给普通打分（全量测试 2026-10-22 boring-rocket：她答完火箭提问后对方的灌水被当成在跟她说，她又接了两句）；
  对方接着 @ 她也不算「刚 @ 过又 @」（`at.perPersonSec`）、不算斗嘴（`topic.atMaxTurns`）。
- **她问了他，他的下一句就是回她**：她这句是在问（问号、「吗 / 要不要 / 好不好…」，`asks()`），问的是她在回的人、或她点了名的人（话里有他的群名片 / @ 他；叫「主人」就是主人，`askedOf`），
  他之后第一句接得上她的（同上「接没接上」的判法，隔着别人在接旁人的不算）标 `asked`，judge 直接 p=1、不掷骰子（她正在这个群说话时照旧等说完补判），
  「行」「好的」「发吧」这种收束句、两个字也算。只管这一句。真群甲（2026-10-23 16:12）：她问主人「要我发群里吗」，主人回「确认，发吧」按在聊打分 p=0.407 没叫醒，120 秒后才醒。
- **结束**（日志 `convo.ended` 带原因）：对方说了收束句；对方连续 `convo.offAfter`（2）句在跟别人说；`convo.idleSec`（120）秒没人续；
  对方连说 `convo.maxUnanswered`（3）句她一句没接；**她说了一句、对方没接**（像真人：说了对方没接、群里在聊别的，就放下）——
  1. 她说完后对方的第一句正经话没接上她：接上 = 短的追问（≤ `convo.chatterMaxChars` 字的问句）、和她那段有共有的词且不比和旁人哪句的少、
     或一个共有词都没有但她开口后旁人没插过无关的话（「对吧，我还录屏了」紧接着她那句）。长问句不算数（可能在问别人），接的是旁人的词就是在跟旁人说；
  2. 她开口之后对方一直没吭声，旁人已经说了 `topic.switchAfter`（3）句和她那段无关的（和话题「换了」同一个数；表情、一两个字不算，引用里的别人的话不算）。
  从她**开口**那刻算、不等说完：她一段说二三十秒，群里照样往下聊。她说话那会儿对方说的，说完按第 1 条判一遍，接的是旁人的就不挂「还没接」。
  真群乙（2026-10-22 23:21–23:29）：她回了青山一句，青山接着跟群里聊他的火箭项目、群友都在 @ 他，他一次没回她，可他每句白话都算「接着跟她说的」，
  她八分钟对他开口七次，「倭寇」那句是他冲另一个群友说的、她回「倭寇是在说谁啊」，被群友吐槽「这个机器人，他认为你在一直和他聊天」。对方回头 @ 她、回复她就再聊上。
  没加新键：判据用现成的 `chatterMaxChars`、`topic.switchAfter`。
- **她说话时对方又说的**：群消息不打断她，那拍大脑被 reply-running 拦下——她说完 1.5 秒后若还有「还没接」的，用那句再叫一次大脑
  （`ctx.mind.wake`，source `group.convo`，日志 `convo.pending` 带 `p` / `wake`）。只靠「reply 完成」那拍的材料不够：模拟器里大脑两次都判「刚说完不用补」。
  **补叫也掷骰子**，用的就是上面「在聊」那套分（judge，同一个 `score`）：那句到达时打的是 p=0「正在说话」，等于没判过，说完补判一次；
  原来一律叫醒，等于直通 p=1 换了个入口（模拟器 convo-follow 六句追问全在她说话时到，六句全补叫、接了五句；真群 17:53「多押韵」也是这么来的）。
  **「还没接」只算她开口之后才到的**：她每开一次口（`utterance.started` 那刻，不等说完），这个群里所有正在聊的人在那之前说的话都算看过了（大脑决定、发言者写这段时历史里都有，
  接没接是她的选择；对方有没看过的话、她接着开口了，就算她又接了他一句，`herLines` 据此衰减），不只给她这段在回的人销账。按说完那刻算会出另一个错：她一段话要说二三十秒，
  对方这期间的第三句到时前两句其实已经在她正说的这段里接了，却累到 `maxUnanswered` 把对话结束（复测 convo-follow 抓到：后两句退回普通打分、没有补判）。复测 2026-10-22（R-1）：她用 append 接住了小林说话时追的那句，这段却被算成回了阿哲，小林的账没销，补叫一次大脑，「取号」说了三遍、「最喜欢哪首」问了两遍。
  材料里也只说「你刚才那段没看到这句；是在问你、要紧的就接上，附和 / 已经说到了的别再说一遍」，不再写成「漏了要紧的话一定要补」。
- **材料**：大脑多一块「你正在和人聊」（和谁、刚才 `convo.lines` 句、哪句「还没接」）；刚因「没接」放下的，`idleSec` 内另列「【你说了对方没接】你上一句说给 X：「…」——X 没理你，接着说的是「…」/ 群里已经在聊别的了」，
  mind-default【群聊】一句「说了对方没接就放下，别追着说」；发言者多一段「【正在聊】你正在和 XX 聊……还在等你接：…」，
  阅读窗口把这段对话整段带上（见下文）。

时段表 `timeRules`：`[{ time: "HH:MM-HH:MM", value }]`，按 `timeZone` 取现在落在哪段（可跨午夜）；默认深夜 0.2、白天 0.7–0.8、晚上 1.2。
每群覆盖 `groups`：`{ "qq:group:123": { "talkValue": 0.5 } }`，只写要改的键（任意配置键都能按群覆盖）；只想调话多话少用下面的 `rates`。

### 每群意愿：倍率 · 好感 · 心情（rates.ts / affinity.ts）

「此刻意愿」= `base` × `talkValue` × 群倍率 × 好感 × 心情 × 时段。面板「群聊意愿」把这几个因子分列出来，看得懂为什么是这个数。

- **群倍率** `rates`（手动）：`{ "qq:group:123": 0.5 }`，0 = 只在有人 @ 她 / 叫她名字时说话，0.5 少说点，1 正常（不写就是 1），最大 3。四种改法改的是同一个配置：
  设置页「群聊策略 → 每群倍率」；面板每行的「少说点 / 多说点 / 只回@ / 恢复」；命令 `/freq set <群号> <0～3|quiet|less|more|normal>`；
  **她自己**用动作 `group.rate`（`{"rate":"less","why":"这群老有人怼我"}`）——大脑材料里有一块「群的感觉」告诉她每个群的好感和倍率，嫌烦就自己调低。
- **好感** `affinity`（自动，从日志推算、不另存）：以 1 为中性，夹在 `min` 0.3～`max` 1.5。
  她在群里说话 `replyWindowSec` 内有人接 +`caught`；被 @ / 叫名字 / 回复她 +`mentioned`；说完没人接 `ignored`（负）；
  冲她说的话里带 `insultWords`（「人机」「闭嘴」…）`insulted`（负）；没事时按 `halfLifeDays` 半衰期回到 1。
  memory 插件的群印象是一段文字、不给数值，这里不解析它；两样大脑都看得到。
- **心情** `mood`：emotion 服务的愉悦度 / 兴奋度相对平时（`baseValence` 0.25 / `baseArousal` 0.45）的偏移，系数夹在 0.6～1.4；平时 = 1，没装 emotion 也是 1。
- **兴趣** `interest.k`：兴趣表在 interests 插件（她自己维护），这里只有一个乘法系数——这句离她的兴趣越近、那条兴趣分越高，接话概率乘得越多（`× (1 + k × 感兴趣程度)`，k 3 = 满分乘 4 倍）；
  开话题时她接的那句感兴趣程度 ≥ 0.3 就算兴趣话题：「话题内主动」起点更高（`topic.interestInTopic`），安全上限也更高（`topic.interestMaxTurns`）。见上文「话题吸引力」。
  原来的 `interest.words` 关键词表和 `interest.value`（「抬到 0.6 × 分」）已删：包含匹配把「火箭队今晚比赛」当航天、「猎鹰九号回收了」反而不认（handbook §9.3）。
- **想不想聊**：此刻意愿低于 `feel.coldBelow`（0.04）算「懒得理」，高于 `feel.warmAbove`（0.12）算「想聊」；
  大脑材料「群的感觉」按群写「此刻想聊 / 一般 / 懒得理（心情不太好，对这个群没什么好感（被怼 3 次））」，让她说得出为什么。


### 手机通知栏（给大脑）

```
【手机上现在的情况】（你一次只在一个会话里；先回找你的，再看群）
- 你刚在：群 900110
- 私聊 七七：2 条未读（1 分钟前）「我明天面试有点紧张，怎么办啊」
- 群 900111：3 条未读，有人 @ 你（刚刚）老王「你们周末都干嘛」/ 糖糖「@沐沐 在吗在吗」
- 你正在用电脑做事（computer#3），群里只回 @ 你的
```

未读 = 她在那个会话最后一次开口之后、别人说的话。只列 `phone.windowSec` 内有动静的会话，最多 `phone.max` 个，
私聊与 @ 她的排前面。大脑提示词（mind-default【群聊】）教它：一次只在一个会话、切换要有由头、先私聊后群、忙时只回必答。

### 一次只在一个会话里（排队）

私聊和两个群同时找她，她可能同时在三处打字。所以（`queue.enabled`）：
- 群里直接找她的话（@、叫名字）到达时她正在**别的**会话里说话：这一拍把感知 kind 换成 `message.queued`（脊椎只认 `message`，就不兜底抢答）；
  大脑照常被唤醒，通知栏里看得到「有人 @ 你」，回不回、什么时候回由大脑定。不再按感知直接入队（原来入队后自动起一条脊椎 reply，
  绕过了大脑；「大脑门控」之后去掉）。
- 大脑要在某个群起 reply 而她正在别处说话：拦下（`intent.blocked`，why `busy-elsewhere`），连 guidance 一起进队列。
- 她说完（reply 结束）且哪儿都没在说话：起队首那个群的 reply（日志 `group.dequeued`，带等了多久），并广播 `reflex.fired`。
  排队期间那个群已经有人起了回复就出队；等超过 `queue.maxWaitSec` 的丢掉，交给大脑看通知栏再定。
- 私聊与网页不排队——这就是「先回私聊再回群」。

### 阅读窗口（大脑与发言者同一个，reading.ts）

发言者：action-reply 先取一大段历史（`historyPool`），过 `reply/prompt` 水线；本插件在群频道里把它换成：
最近 `reading.recent` 条（一分钟超过 `reading.densePerMinute` 句时只读 `reading.dense` 条）
+ 更早里提到她的最后 `reading.mentions` 条 + 她最后 `reading.threads` 次开口各自的前一句与她那句
+ 她正在聊的那段（对方从这段对话开头起的话和她的话，最多 `reading.convo` 条，不被「限总数」裁掉）；按时间排好，总数不超过 `reading.limit`。
私聊与网页对话不动（那是一对一，读全）。

大脑（`beat/gather`，上下文要足够长）：内核给大脑的最近几十条历史是所有频道混在一起的，热闹的群几秒就刷满，
大脑每拍只看得到眼前几句，接不上几分钟前的话。现在唤醒原因里的群，它的那几条换成同一套阅读窗口（候选池从日志取最近 `reading.pool` 条），
别的频道照旧、按时间排回去（`mergeWindow`）。mind-default 同日撤销了「精简拍」，每拍都带全频道历史，群里这几条就是这个窗口。

### 在场的人（people.ts）

群里的人物也要带上下文。窗口只带几十条话，光看几句认不出一个人。窗口里出现的每个人一行（最后说话的在前，最多 `reading.people` 个）：
谁是主人 / 机器人 / 正在和她聊 / 她对他烦不烦、正不理他；最近 `reading.peopleWindowSec` 内在这个群说了几句、@ 过她几次；
**窗口里没带上的他还说过**：比他窗口里最后一句更早、没进窗口的最近 `reading.earlier` 句（纯表情、一两个字的不算）——
几分钟前他说过自己要去成都出差，刷了二十句闲聊之后再问「还记得我去哪吗」，她接得上。
大脑一块【群里在说话的人】（按群分组）、发言者一段【在场的人】（排在记忆之后）。全部从 rooms 的投影现算；长期的「他是谁」归 memory 插件的印象，
它那边同样改成窗口里说过话的人都想起（见 memory README）。模拟器场景 `context-recall`。
第一行是**她自己**（有网名时）：「你自己：网名叫「沐沐小号」，群友写这个名字就是在说你」；**机器人那行**多写：它刚说的三句、群友冲它说过的两句、
「群友说的「鱼」、它的外号、它自称的东西，多半是在说它，不是你」（叫法见下文「谁是谁」）。

**谁是谁：历史里逐句标清楚**（who.ts `tagWho`，发言者的阅读窗口、大脑的「最近对话」都是）：
- 机器人说的，说话人名字后加「（机器人）」；它回复她、紧跟在她之后（中间没别的群友）、或和她最近几句有共有的双字词，加「（机器人，在接你的话）」；
- 群友冲机器人说的加「（在跟机器人 X 说）」：@ 它 / 回复它（没 @ 她；@ 它的话里提到她的网名也算在跟它说）；或者机器人刚说过话（前 4 句、90 秒内）、这句没 @ 她，
  又提到它的叫法、和它刚说的话有共有的双字词、或它紧接着回了这句。**叫法不写词表**：它的名字 + 名字里它自己至少两句话用过的字（「小鱼」说过「我这条鱼是野生的」「天青色瞪眼鱼」→「鱼」），换个形象的机器人照样认；
- 她自己：她的话带上网名（大脑渲染成「你（沐沐小号）」），别人话里出现她的网名标「沐沐小号（就是你）」。
历史里有这种行时，大脑多一块【机器人的话】、发言者多一段同名说明：那是程序的套话，当背景噪音看，想逗一句也可以，但别当成在跟她认真聊、别接到那些话上去；机器人接她的话回不回看她想不想，它不会在意。
真群 2026-10-22 12:35：她该报 DSH 结果，发言者历史最后一句是「Brix：@DeepSeek酱 你不是一个真正的存在」，她当成在跟她说，回了「那你还回我，图啥呢」。
一度整段剔掉，后来改回：她可以回机器人，但要完全明白那是机器人在说无用的废话——所以留着，标清楚。
同日 17:47–17:58（群甲，模拟器 `real-bot-confuse`）：机器人「小鱼」的形象是条鱼，灰灰子说「这鱼怎么感觉没那么聪明」「哦鲸鲸？」她当成说自己（「看本鲸鱼答不答应」）；
IIIBeta2III 说「@小鱼 不要和沐沐小号聊天」她不知道那是自己的网名（「那我跟她自己聊」）——人设里有「你在 QQ 上网名叫…」那句，几千字里模型记不住，得标在那一行上；
小鱼接她的话「挑半天也算心意嘛」「手快是好手快」她看不出是机器人在接她。

### 话题生命周期（topics.ts）

「一个话题可以聊，像正常人一样；聊完了就不接。」每个群一个话题状态，从真源投影：

- **开**：她在群里开口、这个群没有进行中的话题 → 开一个。参与者 = 她回的那个人（按 `Entry.to` 认，和「正在对话」同一个来源；原来取「她开口前别人那句」，
  真群乙 23:21 她回青山，话题却记成恰好在她前面说猫咖的人），关键词 = 那句 + 她这句的双字词。
  例外：群里刚换走的话题（`quietSec` 内、按「换话题」收的尾），她又主动回头接里面的人——不另开，旧话题停在已收尾，碰着它的话照旧压到 `afterClose`
  （原来她这句一出口就开个新话题，旧话题的人和词又成了「她参与的话题还在聊」）。
- **计轮**：她每次主动接（回的不是 @ 她 / 叫她名字的话，也不是正在和她聊的人）记一轮。
- **话题内主动**（进入一个话题之后不该只是被动回复，也可以主动发言）：话题开着、这句在接它（参与者紧接着的回话或关键词重合；
  「紧接着」= 她说完后中间没隔着无关的话，隔着别人的闲话、他冲别人说的不算——模拟器 real-ignored 青山冲白石说的「倭寇」原来被算成她参与的话题），
  接话概率往上到 `topic.inTopic`（0.3；兴趣话题 `topic.interestInTopic` 0.6），每主动接一轮乘 `topic.inTopicDecay`（0.75）——
  追问、补一句、笑一下都行，接得越多越收着；灌水、表情、@ 别人这些往下项照样压得住它。原来是「同一话题只主动接 1 轮」的硬限。
- **收尾**（任一，日志 `topic.closed` 带原因）：
  1. 没人接：她说完 `topic.replyWindowSec`（120 秒）内没人接着说；
  2. 收束句：话题里的人说了 `topic.closers` 里的话（整句就是，或不超过 `topic.closerMaxChars` 字的「哈哈好」「好的谢谢」）；
  3. 换话题：连续 `topic.switchAfter`（3）句和话题不相关（关键词共有 < `topic.minOverlap`，也不是参与者紧接着她的第一句回话）；
  4. 接够了：她在这个话题里主动接满 `topic.maxTurns`（5；兴趣话题 `topic.interestMaxTurns` 8）轮——只是安全上限，平时靠上面的衰减自然收住。
- **收尾后**（`topic.quietSec` 900 秒内）：「接她刚才的话」「还在聊她参与的话题」不再加分；话题里的人说的、或和旧话题相关的话，
  不管是不是问句，接话概率压到 `topic.afterClose`（0.005，要比 `base` 低才压得住）。@ 她 / 叫她名字照旧叫醒大脑——被 @ 后她的回答会开出新话题。
- **斗嘴有个头**：回 @ 她的不算主动轮数，另记 `atTurns`；同一个话题里被 @ 着接满 `topic.atMaxTurns`（2）轮后，再 @ 她（主人、正在和她聊的人除外）
  按「冷 @」处理——脊椎不抢答，大脑看「冷 @」那块自己决定接不接。
- **看得见**：`group.policy` 带 `topic`（进行中几轮 / 已收尾为什么），`why` 里写着「她参与的话题还在聊（她主动接了 1 轮）」「话题已收尾（…），不再接」；
  网页「接话判断」日志与「群聊意愿」表多一列话题；大脑材料多一块「话题」，mind-default【群聊】教它收尾了别硬接、别补话。

### 群里的其他机器人（bots.ts / bot-actions.ts）

真群里另一个机器人（DeepSeek酱）一分钟几条、@ 她、引用她，两个全自动的嘴斗个没完，她还跟着说「剩我们几个数字生命」「主人钱包在滴血」。
真人群友对群里的机器人顶多看一眼。所以：认出来、标上，就不陪它演。

**谁是机器人**（`bots.*`，网页「设置 → 群聊策略 → 群里的机器人」能看能改）：
- `list` 名单：写 QQ 号（或 `qq:号`）。改法：设置页；`/bot mark <号或昵称>`；主人在群里 / 私聊说「那个 XX 是机器人」时大脑用动作 `group.bot`
  （只认主人：意图所在的会话里主人 5 分钟内说过话，网页对话算主人；别人这么说只进自动打分的「被叫机器人」）。
- `learned` 自动认出的：`auto` 开着时，每个人从真源投影攒特征、加权（`weights.*`）超过 `threshold`（0.6）且说过 `minMessages`（3）句就写进来，带分数与理由：

  | 特征 | 分 |
  |---|---|
  | 发过只有机器人发得出来的东西（`botTexts`：官方 markdown 的 `[](%7B%22version`、`mqqapi://`、qqbot 图床、「LLM 响应错误」）——一句就够 | `sig` 0.7 |
  | NapCat 身份是 `roles` 里的 | `role` 0.6 |
  | 号段 `uinPrefixes`（官方机器人 3889…、2854…，10 位以上） | `uin` 0.4 |
  | ≥2 句、三成以上带 markdown 排版（加粗 / 标题 / 列表 / 代码块） | `markdown` 0.4 |
  | 有人发 `/指令` 后几秒（`commandReplySec`）它就应，≥3 次 | `command` 0.4 |
  | 昵称带 `nameWords`（bot / 机器人 / 助手 / AI，英文整词）/ `nameWeakWords`（酱） | `name` 0.35 / `nameWeak` 0.15 |
  | 别人冲着它（@ 它 / 引用它）说 `botWords`（机器人 / 人机 / token机…），引用里的原话不算 | `called` 0.3，≥2 次 `calledMore` 0.45 |
  | 被点名后 `fastReplySec`（3）秒内就回，≥2 次 | `fast` 0.25 |
  | 四成以上是 60 字以上的长段 | `long` 0.2 |
  | 六成以上 [回复] 引用 / 老是一口气连发三句短的 | `quote` 0.1 / `burst` 0.1 |

  后七项是行为类（软）特征，真人也常有，合计最多算 `softCap`（0.5）——光靠它们过不了线，得有一项硬特征。
  这条是真机上吃了亏才加的：一个群友被人 @ 时别人提到「机器人」、他又回得快，被自动认成了机器人。
  用真群日志校过：官方机器人 7 个全认出、真人没有一个过线；DeepSeek酱 这种纯文字、会斗嘴的大模型机器人、
  只应 `/ccb` 指令的白井零号机，自动打分不够，靠名单（面板上点「是机器人」）。
- `notBots` 误判取消：自动打分再高也不算。主人（guard 的 owners）永远不算。

**标上之后**：
- `percept/pre-beat`（本插件最外层那个拦截，2026-10-22 起不再一律不理：可以回，但要完全明白那是机器人的无用废话）：
  它的普通话照常打分、吸引力乘 `bots.attraction`（0.15，不归零），`why` 标「说话的是群里的机器人（程序的套话）」；
  它 @ 她把 kind 换成 `message.cold`（脊椎、排队都只认 `message`，不替她应）、按 `bots.atWake`（0.5）的概率叫醒大脑，日志 `group.policy` 带 `bot: true`；
  回不回由大脑定，材料【读空气】里标着「说话的是群里的机器人」。机器人反复 @ 她也攒脾气（`temper.weights.botAt`），大脑可以决定不理它；
- surface-onebot 发感知前问服务 `bots`（`isBot(platform, id)` / `ignored(platform, id)`），是机器人或她正不理的人就不 `urgent`——@ 她不会打断她正说的话；
- 不算好感（接她的话、@ 她都不算人情）；它的话留在发言者阅读窗口与大脑「最近对话」里、打上「（机器人）」标记（见上文「阅读窗口」）；
- 主人说「你跟它聊两句」→ `group.bot` 的 `chat`（或 `/bot chat`、面板按钮）写日志 `bot.unlocked`：那几句当群友算（不打折、@ 必醒），放进来它的 `unlockTurns`（2）句话或过了 `unlockSec`（300 秒）就恢复（按放进来的句数扣，不按她开口扣：她打字慢，回第二句前它的第三句已经到了）。
  解锁、放行（`bot.allowed`）都从日志投影，重载 / 重启不丢。
- 大脑材料多一块「群里的机器人」（最近有动静的群里谁是机器人、主人有没有让她跟谁聊）；mind-default【群聊】与 persona【要求】教她：
  机器人说的是套话、心里清楚那不是人，可以不理也可以回一句但别斗嘴；被说是机器人就岔开不承认、不说 token / 模型 / 钱包这类系统层的词、不把自己和机器人归成一类。

**看得见、改得了**：面板「群聊意愿」多一列「群里的机器人（不理）」；面板「群里的机器人」逐人列出来源 / 分数 / 理由，
行按钮「是机器人 / 不是机器人 / 重新自动判断 / 解锁聊两句」；命令 `/bot [list] | mark | unmark | reset | chat`。
标记写配置（一次只写一回——配置一写本插件就重载，连写几次会撞车）；自动认出一分钟内对同一个人只写一次，配置没写进去也不会重载个没完。

### 次序

本插件的 `percept/pre-beat` 必须包在 mind-default 外层（大脑在 `next()` 前读 `wake` 决定是否作废正在进行的思考）。
同 order 按 id 字母序首次加载时成立；本插件被热重载（改配置、改文件）后会排到最里层——所以它装上时若发现 mind-default 已在，
就请装配层把 mind-default 也重载一次，让次序恢复。

## 暴露什么

- `percept/pre-beat` 拦截：只管 `channelPrefixes` 下、`kinds` 里的感知（默认 `qq:group:*` 的 `group.message`）。
- 日志 `topic.opened` / `topic.closed`：话题开、收尾（带原因、参与者、她接了几轮）。
- 日志 `convo.started` / `convo.ended` / `convo.pending`：和某人聊上、聊完（带原因）、她说话时对方又说的那几句补叫大脑；`beat/gather` 材料块「你正在和人聊」。
- 日志 `group.policy`：每次判断一条 `{ channel, sender, p, why, wake, factors }`。
- `beat/gather` 材料块「手机上现在的情况」；唤醒原因里的群的历史换成阅读窗口；材料块「群里在说话的人」。
- `reply/prompt` 拦截：群频道的阅读窗口；发言者段落「在场的人」。
- 命令 `/freq [群号]`：每个活跃群此刻的意愿分项（基础 × 话多话少 × 群倍率 × 好感 × 心情 × 时段）、好感为什么、最近几次判断；`/freq set <群号> <倍率>` 调倍率。
- 动作 `group.rate`：她自己调某个群的话多话少。
- 动作 `group.bot`、命令 `/bot`、服务 `bots`（`BotsService`：`isBot` / `ignored`）、日志 `bot.learned` / `bot.marked` / `bot.unlocked` / `bot.allowed`、材料块「群里的机器人」：见上文「群里的其他机器人」。
- 动作 `group.ignore`、日志 `temper.ignored` / `temper.forgiven`、材料块「读空气」、发言者段落「对这个人的态度」、面板「脾气（按人）」：见上文「读空气不写死」。
- `beat/gather` 材料块「群的感觉」：最近有动静的群的好感与倍率。

## 怎么改

`/config set plugins.group-policy.<键> <值>`，键见上文与 `package.json` 的 `mumu.defaults`，改了即时生效。
- 想让她整体安静：`talkValue 0.5`；某个群别说话：`groups` 里给它 `talkValue 0`（@ 她仍会回）。
- 深夜也想聊：改 `timeRules`。
- 群里读得更多 / 更少：`reading.*`（大脑与发言者同一个窗口）；「在场的人」列几个、每人带几句窗口外的话：`reading.people` / `reading.earlier`。
