# interests · 她自己的兴趣表

## 是什么

她可以自己标记自己的兴趣；和真人一样，想聊就聊，不想理就不理，不像聊的话题可以一直无视，直到出现一个真实的话题。
所以她有一张自己维护的兴趣表，每条一个 0～1 的分：人设里写的爱好先种下，聊多了的新话题自己长出来，没兴趣的慢慢淡掉。
表本身不决定她说不说话——group-policy 的「话题吸引力」经水线 `interests/score` 问一声「这句离她的兴趣多近」（语义相近度，不是关键词），乘到接话概率上；大脑和发言者各看到一小段。

## 设计

### 一条兴趣（表 `int_items`）

| 字段 | 含义 |
|---|---|
| 名字 + 描述 + 关键词 | 「摄影」+「拿相机拍照，聊镜头、光圈、构图和修图」+ 相机、镜头、光圈…。拼成一句「摄影：拿相机拍照…。相机、镜头、光圈」去算语义向量（见下文「这句是不是她感兴趣的」），**不拿来做包含匹配**；关键词另外用于面板展示、认「模型换了说法的是不是同一个话题」。描述（列 `descr`）：人设种子写好的（早先种下没描述的，装上时按同名种子补到空的上）；她自己学来的由认话题那次模型调用顺带给一句，只在还没有时写、之后不换 |
| 分 0～1 | 存的是上次改时的值，读时按 `halfLifeDays` 半衰期往 floor 回落（惰性，不跑定时改库） |
| floor | 人设种的 `personaFloor`（0.3）：人设里的爱好淡了也还在；她自己学来的 0：淡到底、`forgetDays` 天没再提就忘掉 |
| 最近触发 | 聊天里最后一次被提到（谁提的都算） |
| 来源 | 人设 / 她自己 / 用户改的。只在新建和用户改时写：她自己聊涨了人设里的爱好，来源还是「人设」 |
| 状态 | 在表里 / 候选（投入聊过但次数没够，只在面板里看得见，不参与打分） |

人设种子在清单 `seed` 里（音乐、冷知识、甜食、猫、航天、新科技，各带一串关键词），**第一次装上时种一次**，之后用户删掉的不会自己长回来。
关键词避开了会误伤的：不放「机器人」「AI」（群里说她是机器人时别被当成聊新科技）、不放单字「糖」（群友叫糖糖）。

### 她自己增删

1. **自动（从日志投影，`watch.ts`）**：她在一个会话里开口就开一段，安静 `settleSec` 秒收段。段里有投入信号——
   主动接了 ≥ `minTurns` 轮、追问（她的话里带问号或 `questionWords`：她口语里的追问多半不打问号，「成色咋样」「天上是什么颜色呀」，验收时踩到的）、说话时带 `positiveEmo` 表情（开心 / 好奇 / 心动…）、
   说了 `likeWords` / `dislikeWords` 里的词——就用一次 `interests.read` 模型调用认出：在聊什么话题、她投不投入、有没有表态。
   词只是「要不要去问模型」的扳机，不从她的话里抠内容（handbook §9.2 不用正则解析模型输出）。
   - 投入：表里有 → +`step.engaged`；候选 → 次数 +1，满 `autoAdd.after`（3）次进表，起步 `autoAdd.startScore`；都没有 → 新候选。
     模型换了说法（「拍照」「摄影」）按名字 / 关键词认成同一个；提示词里也给它已有的兴趣名让它沿用。
   - 关键词：模型每段给的词总混着「图片」「眼睛」「太阳」这种泛词，吸多了无关的话也成了兴趣。所以候选阶段每段的词各记一票，
     进表时只留至少两段都出现过的 + 进表那一段的；进表以后不再从闲聊里吸词（大脑 / 用户明说的照收）。
     这条是验收时看到的：第一轮聊日落，「太阳、江边、光线」跟着进了「摄影」。
2. **显式**：模型判她说了喜欢（stance like）→ 不等次数直接进表、至少起步分再 +`step.like`；说了不感兴趣 → 分压到 0.02（这条留着，记得她不喜欢；人设的也会按半衰期慢慢回到 floor）。
3. **没接就降**：别人的话提到表里的兴趣（语义相近，同下文的打分）、`missWindowSec` 内她没在那里开口、而**叫醒大脑的就是这句**（`beat.opened` 的原因里是这句原文：读空气掷中了它、@ 了她、说完补判）= 看到了没接；
   连续 `ignoreAfter` 次 -`step.ignored`，**扣不穿 floor**（人设的爱好不因为群里没接就没了；已在 floor 以下的不动）。
   大脑没被这句叫醒（群里被接话概率压掉了）不算——不然「分低 → 不唤醒 → 没接 → 更低」越滚越低。原来「这期间大脑因为那个会话醒过一次」就算看到了、扣分也直接扣到 0：
   热闹的群里三分钟总会因为别的话醒一回，真群 10-22 一天把人设的猫从 0.65 扣到 0、航天从 0.63 扣到 0.38，兴趣不再抬接话概率（2026-10-23 真群回放发现，同日改）。
4. **大脑动作 `interest`**：`{"topic":"摄影","like":true,"keywords":["相机"],"why":"…"}`，标「有意思」（+`step.action`，关键词照收）或「没意思」。
   大脑材料里有一句提示它可以这么做。
5. **用户**：网页面板、`/interests set|del`。

重载 / 重启：回放最近一小时日志接着攒；每个会话收过的段、判过的「没接」记在 `int_meta.seen`，不重复算。
回放不做语义打分（模型可能还在加载，一小时的话挨个等会卡住新消息），所以回放那几分钟里「提到兴趣没接」的待定不再判；新事件按到达顺序排队、先打分再投影。
第一次装上时回放只当上下文，不补问模型（不然一装上就把最近一小时的几十段全问一遍）。同一时刻只问一段，队列最多留 12 段。

### 给别人用

- **水线 `interests/score`**（给 group-policy 的话题吸引力）：

  ```ts
  import type { InterestScore } from '../interests/index.ts'
  const r = await ctx.bus.waterfall<InterestScore, InterestScore>('interests/score', { text, score: 0, hits: [] }, async p => p)
  // r.score 0～1 感兴趣程度；r.hits = [{ name, near, score }]：near 相近度、score = near × 兴趣分，感兴趣程度高的在前
  ```

  分 = 最相近的那条的感兴趣程度（不叠加）；无关话题 0；淡到 0.05 以下的兴趣不参与。每条群消息都能调：限时 `semantic.timeoutMs`（300 毫秒），超时、出错、模型还在加载都回 0；
  兴趣表那头还没算好（刚装上 / 重载后预热没跑完、表里刚加了一条）时这一次至少等 1 秒，不回 0。
  用水线不用服务：本插件改配置会重载，注入服务的插件会被连带重载；没装本插件时调用方拿回初值 0，自然降级。
- **`beat/gather`**「你最近感兴趣的」：分 ≥ 0.3 的前 `show` 个；唤醒原因离兴趣近时加一句「刚才这句聊到了你感兴趣的：…」（同一个语义分）。

### 这句是不是她感兴趣的（语义打分，`semantic.ts`）

该看的是这句是不是她喜欢的话题、是就乘上唤醒概率，不该靠代码做字面匹配。原来是关键词包含：
「火箭队今晚比赛」算航天、「猎鹰九号回收了」反而不算。现在：

- **先剥壳**（`clean`）：表现端写的占位与转发壳——`[图片]`、`[表情包：…]`、`[聊天记录：…]`（里面套着 `[图片]` 也一层层剥）、`[回复 某人「…」]`、
  `@某人`、链接——不是这个人在说的话，剥掉；语音转写留内容；剩下不足 2 个字（字母 / 汉字，纯标点数字不算）的直接 0、不去算。
  10-23 回放里一条只有转发壳的「[聊天记录：墨羽：[图片]；…]」对音乐相近 0.53。看图的描述（`[图片：一只猫…]`）也剥：那是模型看图写的，不是他说的。
- 每条兴趣拼成「名字：描述。关键词、关键词…」算一个句向量，每条消息算一个，取余弦相似度，**再两头都减「平时」**，用 `semantic.background` 一组日常闲话
  （「好的」「吃饭了没」「今晚加班到十点」「乖乖叫哥哥」…，60 句，覆盖吃饭、称呼、工作、起哄）量：
  - 兴趣的平时 = 它和这些闲话的平均相似度。不减的话，关键词里混着「紧张、准备」这种泛词的兴趣（面试）对「在吗」「上班好累」都有 0.45 上下；
  - 这句话的平时 = 它离**最近的 5 句**闲话有多近，比闲话彼此之间（同样取最近 5 句）近出多少。「吃了吗」「中午吃啥」贴着吃饭那几句、「狗修金」贴着称呼那几句，
    减得多；「猎鹰九号回收」离哪句闲话都远，减得少。只减兴趣那头时「吃了吗」对甜食 0.41、「中午吃啥」0.69；取全部闲话的平均（而不是最近几句）会被别的几十句冲淡。
  减完 ≤ `semantic.threshold`（0.16）算不相关，≥ `semantic.full`（0.26）算满，中间线性 = **相近度**；
  **感兴趣程度** = 相近度 × 那条兴趣自己的分。向量按文本缓存（LRU `cacheSize` 条）：兴趣改了关键词 / 描述 = 文本变了，只重算那一条；重复的消息不重算。
- **预热**：插件装上就在后台加载模型、把闲话基线和整张兴趣表的向量与平时算好（`Semantic.warm`），之后每句群消息只算它自己（几毫秒）；
  兴趣表变了（`interests.changed`）再预热一次，缓存着的不重算。原来重载 / 重启后第一句要连整张表和闲话一起算，虚拟机上 513 毫秒，超过 300 毫秒限时那句是 0。
- **默认在本机 CPU 上算**（`semantic.via: local`，`local.ts`）：transformers.js 跑 ONNX 量化模型 `Xenova/bge-base-zh-v1.5`，不依赖 4090 和网络。
  模型第一次用时从 `remoteHost`（默认 hf-mirror.com，国内直连）下到 `cacheDir`（`data/models/`，不进 git），之后离线加载；插件装上就在后台加载，加载完之前打分是 0。
  阈值是按这个模型调的（`scripts/fake-onebot` 的 `interest-sem` 场景量过）；换模型要重调 `threshold` / `full`。
  选型（2026-10-23 在 Mac 上，用真库的兴趣表比过）：bge-small-zh、multilingual-e5-small、jina-v2-base-zh 不减平时、减了平时都分不开；
  Qwen3-Embedding-0.6B（约 600MB）减了平时和 bge-base 差不多；bge-base-zh 约 100MB、一句几毫秒，取它。
  bge-large-zh（约 320MB、常驻内存近 800MB）在下面的对照集上也比过：两头减平时后 AUC 0.97，不比 base 的 0.98 好，所以没去量虚拟机扛不扛得住，不用它。
  bge 的检索前缀（「为这个句子生成表示以用于检索相关文章：」）在这里反而更差，所以 `query` 默认空。
  **它仍然有噪声**，见下面对照集里还错的几句。要准就换「让模型打分」（见下条），代价是慢和要开着 4090。
- **退路：让聊天模型打分**（`semantic.via: model`）：一次调用（角色 `interests.score`，提示词在 `read.ts`）回 `{"topic","near"}`，同样按文本缓存。
  4090 上的 NInfer 不提供 `/v1/embeddings`（2026-10-23 探过，404），所以那边只能走这条。同一批 18 句在 4090 的 qwen3.8-27b 上全对
  （没关键词的航天话 0.95～1，字面带「火箭」的和灌水全是 0），但一句要 0.6～1.9 秒、引擎还是按需启动的：要把 `timeoutMs` 调到 2000 上下、给角色绑 `maxTokens` 30 左右。
- 依赖：**`@huggingface/transformers`**——在 Node 里用 CPU 跑 ONNX 句向量模型的现成库（自带分词器、自动下载与缓存模型），不用另起 Python 服务；
  动态 import，没装上时插件照样加载、兴趣分恒为 0（日志 `interests.failed { stage: 'score' }`，一分钟最多记一次）。
  它带着 `onnxruntime-node`（各平台预编译的二进制就在包里）和 `sharp`（图片处理，这里用不上但是它的硬依赖），`npm install` 即可，不用全局装东西；
  npm 的 allow-scripts 会拦下 onnxruntime-node 的 postinstall，不影响——那个脚本只在 Linux 上下 CUDA 版，CPU 版的二进制已经在包里。
- **发言者段落**「你最近在意的事」（`PROMPT_ORDER.memory`，一句）：同样前 `show` 个，「聊到了可以多说两句、追问；没聊到别硬扯」。

### 对照集（2026-10-23，`scripts/interest-eval.ts`）

20 句真在聊她的兴趣、20 句字面像 / 群里常见但不是（头三句是 10-23 早上线上和克隆核对挂掉的，末两句是占位壳），兴趣表用人设种子（分都当 1，看的是相近度）。

只抬阈值：假的少了，真的也一起没了（AUC 不变，阈值只是在同一条线上挪）；只扩闲话、只加描述各好一点；真正拉开的是「这句话那头也减平时」。
这句那头只减不加（离闲话远的话不往上抬）也试过，AUC 掉回 0.83——「猎鹰九号回收」这种离所有闲话都远的话，正是靠这头被抬上来的；代价是有具体话题的无关话也被抬一点（话题负例 0/15 → 4/15）。

选定：两头减平时（最近 5 句）+ 60 句闲话 + 描述 + 0.16 / 0.26——均值差最大，20 句真兴趣全过 0.5。
**还错的**：「火箭队今晚比赛谁去看」被认成音乐（「今晚…去看」像去看演唱会；改前 0，这句变差了）、「章鱼有三颗心脏」「香蕉是浆果」认成航天 / 甜食
（冷知识是一种说法而不是题材，向量认不出，好在都认成了她别的兴趣）、「原来是你偷吃了我的饼干」「原神新版本的角色抽不抽」沾甜食 0.4 上下、
「电动车电池换一个多少钱」新科技 0.5。用克隆实例那张表（`--db`，猫的关键词里混着「眼睛、图片」、火锅没有描述）时「狗修金」→ 猫 0.34（改前 1.0）、
「火箭队今晚比赛谁去看」→ 火锅 1.0（火锅只有「火锅：毛肚」几个字；补上描述后降到 0.24，但航天仍有 0.78）。
模拟器（克隆，10-23 下午）：interest-sem、boring-rocket（前 40 句灌水开口 0）、flood、interest-learn 过；real-convo-spam「狗修金」×1.99 把在聊的 0.5 乘到了 p=1。

## 暴露什么

- 表 `int_items`、`int_meta`（storage-sqlite 的 `db`，日志清空也留着）。
- 水线 `interests/score`，类型 `InterestScore` 随 `index.ts` 导出。
- 动作 `interest`；命令 `/interests [score <文字> | set <名字>=<分> | del <名字> | flush]`。
- 日志：`interests.read`（每次模型认话题的结果与信号）、`interests.changed { name, from, to, state, why, by: chat|ignored|action|user }`、`interests.removed`、
  `interests.failed`（认话题失败 `{ channel, error }`；语义打分失败 `{ stage: 'score', via, error }`，一分钟最多一条）。
- 模型角色 `interests.read`、`interests.score`（后者只在 `semantic.via: model` 时用；provider 里没绑就走 `default`）。
- 依赖 `@huggingface/transformers`（理由见上文「这句是不是她感兴趣的」）；模型文件在 `data/models/`。
- 网页：面板「兴趣」（`near: 'persona'`，人格抽屉底下也有；加一条 / 调分 / 每行 +0.1 -0.1 删掉，改表即时生效、不重载插件）、状态卡「兴趣」、`GET /api/interests/score?text=`。
- 模拟器验收剧本 `interest-learn`（`scripts/fake-onebot/interest-scenes.ts`，点名才跑）。

## 怎么改

`/config set plugins.interests.<键> <值>`，或网页「设置 → 兴趣」：`halfLifeDays`（衰减速度）、`autoAdd.after`（投入几次进表）、`autoAdd.startScore`、
`step.*`、`ignoreAfter`、`settleSec`、`positiveEmo`、`likeWords` / `dislikeWords`、`show`；语义打分 `semantic.*`（怎么算、模型、阈值、限时、下载源）。种子 `seed` 只在第一次装上时用。
`/interests score <文字>` 打印感兴趣程度、每条相近的兴趣（相近度 → 感兴趣程度）和这次花了几毫秒。
改了闲话、阈值、描述或换模型，先跑 `npx tsx scripts/interest-eval.ts`（对照集，`--grid` 比几组参数、`--db <库>` 用某个库的兴趣表、`--text "一句|另一句"` 现场看）再定。

**虚拟机上线**：在后端目录 `npm install`（装上 `@huggingface/transformers` 与 win32 版 `onnxruntime-node`，不全局装东西），
确认 `node_modules/onnxruntime-node/bin/napi-v6/win32/x64/` 里有 `onnxruntime_binding.node`；重启后端，第一次加载会从 hf-mirror.com 下约 100MB 到 `data/models/`，
下完前兴趣分是 0。下不动（没网）就把 Mac 上的 `data/models/Xenova/bge-base-zh-v1.5/` 整个拷过去。
